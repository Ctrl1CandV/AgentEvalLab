# Task Collection

## Purpose

Keep a small set of tasks that exercise distinct, useful behaviors and can be scored with traceable evidence. Each task belongs to a family; related variants are not counted as independent evidence.

## Selection criteria

- State a concrete user goal, starting state, deliverables, and acceptance conditions.
- Prefer tasks with multiple legitimate implementations and explicit invariants.
- Separate public examples from hidden grader cases.
- Avoid copying well-known benchmark prompts or repository examples.
- Record provenance, dependencies, runtime, tool needs, and known exposure.
- Include at least one valid reference and targeted negative implementations before promotion.
- Keep tasks that require human judgment marked as pending until a reviewer completes the relevant form.

## Current candidate families

- Engineering: data validation, resumable processing, resource management, resource indexing, and continuous maintenance.
- Reasoning: shift scheduling and derivation-error analysis.
- Tool use: paginated document evidence recovery.
- Frontend: an original static landing page with behavior and accessibility checks.

Candidate status does not imply calibration or readiness for live model comparison. See the package manifest and calibration record for each task.
