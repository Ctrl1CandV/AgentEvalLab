二、本次的目标

从 PLAN-007 的 Phase 0 开始，按顺序实施。Phase 0 到 Phase 3 不需要付费的模型运行，请自主完成，每个工作包结束时提交一次。到 Phase 4（第一次付费运行）之前停下来，向用户汇报，并请用户确认 D1–D7 和 Phase 4 的 token 额度；用户已经明确批准的事项除外。

Phase 0 的重点：建立 v1 证据表；修复 T2 的覆盖漏洞（未知请求编号下的操作逃过评分），加上全局终态检查和负例测试，并对所有模型统一重评分；对高分的 v1 题族做成功审计；同步文档。Phase 1 建立 v2 的度量层（manifest v2、grader 结果 v2、src/scoring、outcome.json、报告 v2），并且不跑模型，先用 AE 和 R3 证明它能用。Phase 2 按层级重组题库，给保留的题族写能力卡，实现只读运行时挂载、无工具的只答题配置和仓库工作区。Phase 3 离线搭建并验证新题族：AR（ARC-AGI）、ER（SWE-bench-Live 的近期真实 issue）、AP 原型、VIS v2、AE 0.2.0。

三、必须遵守的原则

1. 每次只改一类东西。不要同时改题目、权重、模型、预算和会话策略，否则无法判断哪一项改动起了作用。
2. 每个题族在任何付费运行之前都要有能力卡。能力卡第 4 节写不出"难点在哪里"的题，不要做。
3. 难度不能来自隐藏要求、含糊表述、格式陷阱或框架限制。每一项隐藏检查都必须能追溯到公开的任务契约。
4. 分数以独立任务为单位，开放式题目报告原始值，并且不封顶。不要为了把某个模型压到 80 分以下而调整权重或缩放分数。
5. 数据切分（dev、validation、holdout）按结构分组，并在第一次试跑之前固定。validation 每次冻结只用一次，holdout 只在发布冻结之后使用。
6. 失败和成功都要审计。每一项扣分都必须是模型自己的问题；每一次通过都要经过成功审计确认是真的通过。
7. 版本不可变。修改评分器或锚点就升版本号，并对所有模型统一重评分；旧数字保留旧版本，不重新贴标签。
8. 沿用用户已有的决定：思考档位用中档；temperature 为 0；token 按固定单位计量，缓存输入全额计入，不按价格计；效率只报告、不计分；预算开场告知，用到 50%、75%、90% 时提醒；格式错误扣 20% 的规则改为单独一列报告，是否保留在主分数里等用户决定 D2。
