# Evaluation Method Notes

This project uses a task-based evaluation design with explicit contracts and preserved artifacts.

## Method choices

- Score each task against its own requirements instead of combining unlike abilities.
- Keep candidate generation separate from trusted evaluation.
- Use independent reference implementations to test acceptance of legitimate alternatives.
- Use targeted mutations to test detection of selected defects.
- Repeat deterministic checks to identify grader instability.
- Preserve incomplete, pending, resource-limited, and infrastructure-failed states separately.
- Compare models only under the same pinned task, prompt, tool profile, and budget.

## Limits

A reliable grader can still score an unrepresentative task. Offline calibration does not estimate task difficulty, model ranking stability, or real-world transfer. Those questions require a bounded pilot and a reviewed analysis.
