# PLAN-003: Core Evaluation Work

Updated 2026-10-10.

## Goal

Maintain a reproducible Pi Agent harness for selected engineering, reasoning, tool-use, and frontend tasks. Keep task outcomes, human review, runtime, usage, and delivery evidence separate.

## Completed offline work

- **M1: Basic harness.** Plan validation, Pi execution, tool profiles, event persistence, artifacts, and per-run reports.
- **M2: Objective task packages.** Versioned manifests, public projections, trusted graders, requirements, and offline reference/mutation calibration.
- **M2L: Continuous engineering.** Five-stage trajectory execution, shared workspace and session, stage budgets, public feedback, snapshots, and regression/retention metrics.
- **M2R: Scoped reliability fixes.** Stage-isolated public checks, disposable checker snapshots, candidate timeout attribution, overlapping and repeated page evidence, cross-page JSONL records, CSV row boundaries, and explicit clarification targets.
- **Repository migration.** Core source, documentation, and retained task material are being prepared for an English-only handoff.

## Remaining work

1. Review the English task instructions and confirm translated contracts preserve the intended cases.
2. Complete the visual rendering and human-review workflow when its rendering environment is available.
3. Prepare a bounded live pilot only after selecting providers, request limits, output limits, timeouts, and a cost ceiling.
4. Keep conclusions limited to observed task versions, models, prompts, tools, and budgets.

## Evidence status

Offline package calibration covers selected references and mutations. It does not establish model difficulty, discrimination, broad construct validity, or real-provider behavior. Historical calibration records are task-specific and are not model scores.
